# Theory - CICS, BMS, COBOL and transaction flow

A CICS transaction is not the same as a batch COBOL program.

In batch, the job executes a program directly and writes to `SYSOUT`. In CICS, the user enters a transaction ID from a terminal. CICS resolves that transaction to a program resource, loads the program, and the program interacts with the terminal through CICS commands.

For this lab the chain is:

```text
TRANSACTION(HOLA)
        ↓
PROGRAM(HOLA)
        ↓
COBOL CICS program
        ↓
EXEC CICS SEND MAP('HOLAMP') MAPSET('HOLAMP') FROM(HOLAMPO)
        ↓
MAPSET(HOLAMP)
        ↓
3270 BMS screen
```

The BMS source is not the final screen. It must be assembled. In this lab the same BMS source is processed in two modes:

- `SYSPARM(MAP)` creates the physical map load module.
- `SYSPARM(DSECT)` creates the symbolic map copybook used by COBOL.

The COBOL program includes `COPY HOLAMP` because `SEND MAP ... FROM(HOLAMPO)` requires the symbolic output area generated by BMS.
